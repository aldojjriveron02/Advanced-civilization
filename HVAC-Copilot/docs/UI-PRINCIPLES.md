# UI Principles

The field UI is designed for fast comprehension while a technician is working.

## Rules
- One primary action per screen.
- Large readable typography; never rely on tiny labels.
- High contrast and clear status hierarchy.
- Use plain HVAC language first; technical detail can expand when needed.
- Measurements always show value + unit together.
- Distinguish **Observed**, **Calculated**, **Manufacturer Data**, **Possible Cause**, and **Confirmed** states visually and semantically.
- Safety warnings interrupt the workflow when necessary rather than being buried in text.
- Minimize typing: camera, voice, large controls, and quick-select inputs are preferred.
- Every diagnostic recommendation shows the evidence that led to it.
- Avoid dense dashboards during active service work; progressive disclosure keeps the screen understandable.
- Support accessibility: Dynamic Type, VoiceOver labels, touch targets, and dark mode.

## First iPhone workflow
1. Start Job
2. Equipment
3. Customer Complaint
4. Measurements
5. Guided Diagnosis
6. Findings / Next Action
7. Service Report

The UI should make the next useful action obvious without requiring the technician to interpret an AI paragraph before proceeding.
